## Breaking changes for consumers

- The package now targets Umbraco 17.8.1 or later on .NET 10 only. The v13 build stays on `v13/main`.
- `SpellCheckValueSetBuilder`'s public constructor takes `ILanguageService` instead of `ILocalizationService`
  (`ILocalizationService` no longer exposes what the builder needs in 17). Anyone constructing it by hand must pass the new service;
  resolving it from DI is unaffected.
- The package version moves to `17.0.0-alpha` (version-aligned with the CMS), so it no longer collides with the `1.0.0-alpha`
  already on NuGet from `v13/main`.
- The v13 backoffice client had no public surface: `lang/en.xml` held an empty area and `SearchSpellCheckManifestFilter` was internal.
  Nothing consumers could reference was removed.

## Backport candidates

- **Spell check index stays empty: the builder writes no `__Published` or `path` field** (`aa90996`).\
  Class: safe for a patch release (no public API change, no migration, no new dependency).
  - `v13/dev` (`develop` line): **shows, confirmed by a run** on Umbraco 13.6.0 (fresh install, Clean content): `SpellCheckIndex` had 0 documents after first boot, after a manual rebuild and after a publish, while the builder produced 50 value sets. Safe for a patch release. Not picked yet.
  - The fix on `develop` is only the two fields in the builder (the `aa90996` change). The filtering, populator and handler changes in `8c9cb29` are separate and bigger; port them separately, if at all.

## Follow-ups

- The test project reports `NU1902` for `MailKit 4.14.0` and `MessagePack 3.1.4` (transitive from the CMS test package). Not caused by the package; left as is.

- Protecting a page on a live site keeps its words in `SpellCheckIndex` until the next rebuild: the package doesn't handle `PublicAccessCacheRefresherNotification` (the CMS does, `ContentIndexingNotificationHandler`, `release-17.8.1`). Existing gap on every line.
- `SpellCheckIndexPopulator` and `RebuildOnPublishHandler.IndexPublishedDescendants` both write the "live = published, not trashed, parent live" rule, and the populator loads unpublished items in order to drop them. A shared helper and a published-only query would fix both, but the second needs a public constructor change.
- Older faults, not caused by the upgrade: a `RefreshBranch` payload only reindexes the node in places, a non-payload message such as `RefreshAll` throws `NotSupportedException` in `RebuildOnPublishHandler`, invariant properties on variant content are read with a culture (likely null) so their words miss `word_xx`, `release.yml` only fires on `x.y.z` tags so `17.0.0-alpha` won't trigger it, and rich text puts raw HTML in the `word` field on v13 (check on v17).
- The first-boot rebuild runs about a minute after start and the package logs nothing for it; failed `Attempt`s from `RebuildIndexAsync` aren't logged (`BuildOnStartupHandler.cs`).
- The 17.8.1 `umbraco-package-schema.json` has a malformed `type` entry and can't be compiled by ajv: worth reporting to the CMS team.
