# Upgrade to Umbraco 18

From `17.8.1` to `18.3.1` (tag `release-18.3.1`).
Branch `v18/feature/upgrade-18`, cut from `v18/dev` (`d4ac2b3`, the merged v17 port). `v18/dev`, `v18/main`, `v19/dev` and
`v19/main` were created from the same commit when PR #8 merged.

**Targets CMS release:** `release-18.3.1` (stable, 5 November 2026). The package's own version stays a pre-release
(`18.0.0-alpha`), as `17.0.0-alpha` does on the v17 line.

## Inventory

- **Spike compile on 18.3.1 passes** (verified)\
  Source: scratch worktree of `v18/dev` with the floor `[18.3.1, 19.0.0)` and the test site on `18.3.1`:
  `dotnet build --no-incremental` gives 0 errors and no `CS` warnings, and `dotnet test` passes 64/64. So there is no compile
  break and nothing newly obsolete (second `CS0618` pass).\
  Hits: nothing to fix. The bump is the task.
- **Target framework unchanged: .NET 10**\
  Source: `release-17.8.1:Directory.Build.props` and `release-18.3.1:Directory.Build.props` both `net10.0`.\
  Hits: none.
- **Shared dependencies unchanged: Examine 3.10.0, Lucene.Net 4.8.0-beta00018**\
  Source: `Directory.Packages.props` at both tags; `dotnet list package --include-transitive` on the spike shows `Lucene.Net`,
  `.Suggest` and every `Lucene.Net.*` at beta00018.\
  Hits: none. The package's own `Lucene.Net` / `Lucene.Net.Suggest` references already match.
- **`ILocalizationService` removed** (18.0.0-beta1)\
  Source: umbraco/Umbraco-CMS#22677, and `UmbracoContentIndex` / `ContentValueSetBuilder` now take `ILanguageService`.\
  Hits: nothing. The v17 port already uses `ILanguageService` in `SpellCheckValueSetBuilder`.
- **`IContentService` now extends `IPublishableContentService<IContent>`** (18.0.0)\
  Source: `release-18.3.1:src/Umbraco.Core/Services/IContentService.cs` (members moved to the base interface).\
  Hits: `SpellCheckIndexPopulator`, `RebuildOnPublishHandler` call `GetPagedDescendants` / `GetById` / `IsPathPublished`; the spike
  compiles and the tests pass, so the members are still reachable. Needs the Examine smoke to prove the behaviour.
- **`ContentCacheRefresher` internals changed, payload unchanged** (18.0.0: #22369 element cache, #22629, #22302)\
  Source: `release-17.8.1` vs `release-18.3.1:ContentCacheRefresher.cs`: only constructors and injected services changed.
  `JsonPayload` (`Id`, `Key`, `ChangeTypes`, `Blueprint`, `PublishedCultures`, `UnpublishedCultures`) is identical.\
  Hits: `RebuildOnPublishHandler` reads `ContentCacheRefresher.JsonPayload`: no change needed.
- **Examine and search code barely changed** (17.8.1 to 18.3.1)\
  Source: `git diff --stat release-17.8.1 release-18.3.1` over `src/Umbraco.Examine.Lucene`, `src/Umbraco.Infrastructure/Examine`
  and `/Search`: 8 files, small. `ContentValueSetValidator`, `UmbracoExamineIndex`, `IndexPopulator`,
  `ContentIndexingNotificationHandler` are unchanged. `UmbracoContentIndex` changed only its `ILanguageService` type, and
  `UmbracoTempEnvFileSystemDirectoryFactory` / `UmbracoApplicationRoot` changed (temp folder handling).\
  Hits: `SpellCheckIndex` mirrors `UmbracoContentIndex`; its behaviour is unchanged. The temp-directory change needs the
  first-boot and `LuceneDirectoryFactory` check in the smoke.
- **CMS data migration `V_18_0_0.MigrateSingleBlockList`** now runs automatically on upgrade
  (`UmbracoPlan.cs`, and the docs' "Implement `ITypedSingleBlockListProcessor`" note).\
  Hits: the package stores no block JSON, but it reads Block List and Block Grid values to build its word list. A task checks the
  words from those properties after the migration, in the upgrade smoke. The package has no custom property editors, so the
  `ITypedSingleBlockListProcessor` note does not apply.
- **Other 18 breaking changes checked, none hit the package**: Swashbuckle replaced by `Microsoft.AspNetCore.OpenApi`, media
  recycle bin protection, the `18.0.0` release notes' only package-relevant item (#22677). The package has no OpenAPI documents,
  controllers or media handling. Source: docs `18/umbraco-cms/get-started/upgrading-and-migrating/version-specific.md`.
- **Hop allowed**: the docs say Umbraco 18 upgrades from 16.4 or later; this goes from 17.8.1.
- **Frontend**: none. `umbraco-package.json` has `extensions: []`. Manifest validated for 17.8.1 only; re-check against the 18.3.1
  schema in the markers task.
- **Persistence**: no EF Core in the package.
